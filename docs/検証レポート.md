# おとつみき 検証レポート

検証の方法：`tools/audit.js`（自動テスト。Chromium で実際にアプリを動かして測定）
くりかえし測るとき：`python3 -m http.server 8765` でアプリを開いた状態で `node tools/audit.js <出力フォルダ> <名前>`

## 1. 操作性

| 項目 | 直す前 | 直したあと |
|---|---|---|
| タブレット：タップで音を置ける | OK | OK |
| タブレット：指で押しにくい部品（高さ32px未満） | 85個 | **3個** |
| 押しても5秒間ボタンがかくれる（音名の表示が重なる） | あり | **なし**（下に表示し、下のボタンも押せる） |

直したこと
- タブレット（指で操作する端末）では、ボタン・選択欄を高さ40px以上に
- 「指でなぞったとき：音を置く／スクロール」と「音のドラッグ：自動／のばすだけ／動かすだけ」を「👁 表示」にまとめた
- ポップアップは、外をおすと閉じる

## 2. 音色の種類

| 項目 | 直す前 | 直したあと |
|---|---|---|
| 旋律楽器 | 53種（電子音のみ） | **64種**（うち**51種は本物の録音**も選べる） |
| 打楽器 | 56音（電子音） | 56音（うち**34音は本物の録音**） |
| 楽器ごとの音量の差（電子音） | 22dB | **9dB** |
| 楽器ごとの音量の差（録音） | — | **7dB** |
| 1音で音割れする楽器 | 0 | 0 |
| 音の高さのずれ（15セント超・電子音） | 0種※ | コーラス（16セント） |

※はじめの測り方（自己相関）に偏りがあり、鉄琴などが「ずれている」と出ていたが、測り方を直したら問題なかった。

録音で音の高さが15セント以上ずれて出たもの：パイプオルガン・アコーディオン・リコーダー・チューブラーベル・ティンパニ・太鼓。
これは本物の楽器の性質（アコーディオンはわざと少しずらしたリードを重ねる、ティンパニや鐘は倍音が整数倍でない、太鼓は音程がはっきりしない）によるもので、故障ではない。

録音の出どころ：FluidR3 GM サウンドフォント（Frank Wen 作、CC BY 3.0）。3半音ごとの録音を使い、間の音は高さを少しずらして鳴らす。録音がない音（カスタネット・すず・シェーカーなど）は電子音で鳴らす。
見つけて直した不具合：コントラバスの高い音で録音が無音になっていた → 無音の録音は自動で使わないようにした。

## 5. レイテンシー（反応の速さ）

| 項目 | 直す前 | 直したあと |
|---|---|---|
| マスを押してから音を鳴らす予約まで | 10ms | **0ms**（すぐ鳴らす） |
| マスを押したときの処理時間 | 3.6ms | 1.8ms |
| 再生ボタン→最初の音（2回目以降） | 80ms以上 | **51ms** |
| 再生ボタンの処理時間（2回目以降） | 約40ms（毎回） | **1ms以下** |
| 再生中の最悪の1コマ | 567ms（固まる） | **17ms**（なめらか） |
| 大きな曲（64小節・6パート）の描画 | 2.5ms | 2.2ms |

直したこと
- 響き（リバーブ）の部品を毎回作っていた → 1回だけ作って使い回す（1回目の再生だけ約40ms）
- 録音の読み込みを1つずつ順番に行い、画面が固まらないようにした
- 試し聴きの音を 10ms 待たずにすぐ鳴らす

注意：「音声出力の遅れ」（パソコンやタブレットの音声装置そのものの遅れ、測定環境で約40ms）はブラウザと端末で決まり、アプリでは変えられない。

## 8. 見た目（デザイン）の整理

- 絵文字（index.html 約40種・app.js 約25種）を、太さと形をそろえた線画アイコン55個に置きかえ（音楽の記号 ♯♭♩ などは楽譜の記号なので残す）
- 色はアクセント1色（藍色）＋グレーに整理。トラックの色・音の高さの色（学習用）は少し落ち着いた色に
- ボタンは枠なし（さわると薄く色がつく）、関係のあるボタンはグループでまとめる
- トラックのカードを軽く（細い色の帯＋えらぶと薄い藍色）
- ダークモード：鍵盤の色・通知の色を調整
- 楽譜：五線の外にはみ出す音（加線）の分だけ段の間隔を自動で広げ、となりの段とぶつからないように
- タブレットのボタンの大きさ（40px以上）を保つことを再確認（押しにくい部品 3個のまま）

## 9. 清書（浄書）の品質

- **ト音記号の位置**：これまでは端末のフォントの文字（𝄞）で描いていたため、端末によって位置がずれていた。楽譜専用フォント **Bravura**（Steinberg、SIL OFL 1.1）の形のデータを取り出し（`tools/build_glyphs.py` → `js/glyphs.js`）、SMuFL の決まりどおり**ト音記号は第2線（ソ）、ヘ音記号は第4線（ファ）を原点**にして図形で描くように変更。画像で確認済み
- 符頭・休符・臨時記号・拍子記号・旗・付点・アーティキュレーション・フェルマータ・強弱記号・テンポ記号・3連符・大譜表のかっこも同じフォントの形に
- 自動調整：歌詞・階名・臨時記号の幅を考えた間隔、段ごとの小節数をそろえる（最後の段だけ間延びしない）、4/4拍子の8分音符は2拍ずつ連桁、調号と拍子記号が重ならない幅計算
- 楽譜エンジンのテスト（`tools/notation_test.js`）はすべて合格のまま

## 10. 楽器えらびの絵・スマホの楽譜入力・はじめの画面

## 11. 改善（軽さ・曲の組み立て・使いやすさ）

- **読みこみを軽く**：楽器の録音を1音ずつの小さな MP3（`samples/mp3/`）にし、曲で使う高さだけを先に読む。サンプル曲で 約2.7MB → 約0.33MB。2回目からはサービスワーカー（`sw.js`）がキャッシュから出すので、オフラインでも開ける。`file://` で開いたときは今までの `samples/*.js` を使う
- **2声部**：1つの段に上下2つのメロディ（声部1＝ぼう上、声部2＝ぼう下）。MusicXML の書き出し・読みこみも対応
- **とちゅうの拍子・調の変化**：小節ごとの長さを持つ「小節の表」に作りかえ、再生・メトロノーム・マス目・楽譜・MIDI・MusicXML すべて対応
- **D.C./D.S./コーダ/Fine/セーニョ**：楽譜に記号と文字、再生もそのとおりの順番
- **印刷のページ分け**：A4 に段のとちゅうで切れないように分け、ページ番号つき
- **使い方ツアー**：はじめて曲を作るときに自動で出る（パソコン8ステップ／スマホ7ステップ）
- **チェロとコントラバスの絵**：コントラバスはなで肩の大きな胴＋となりに小さな人で「人より大きい」ことがわかる絵に。ビオラの絵も追加
- **タッチで説明**：ボタンを長おし（約0.45秒）すると説明が出る。そのときボタンは押されない
- **MP3書き出し**（lamejs、LGPL）
- テスト：`tools/structure_test.js`（新しい機能）、`tools/sample_load_test.js`（録音の読みこみ）を追加。既存のテストもすべて合格
